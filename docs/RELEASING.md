# Сборка и выпуск версий

## Как это устроено

| Файл | Когда запускается | Что делает |
|---|---|---|
| `.github/workflows/ci.yml` | push в `main`, pull request | тесты на Windows, macOS, Linux → пробная сборка установщиков (Artifacts, 7 дней) |
| `.github/workflows/release.yml` | push в `main` с новой версией в `package.json`; вручную — Run workflow | тег и черновик релиза → тесты и сборка на трёх ОС с выкладкой в него → публикация |
| `.github/workflows/build.yml` | вызывается из двух предыдущих | сама сборка electron-builder |
| `.github/dependabot.yml` | раз в неделю | PR с обновлениями npm-пакетов и actions |

Что получается в релизе:

| ОС | Файл | Автообновление |
|---|---|---|
| Windows 10/11 x64 | `Orion-Setup-X.Y.Z.exe` | да, дифференциальное (качается только изменённое) |
| macOS Apple Silicon / Intel | `Orion-X.Y.Z-mac-arm64.dmg`, `…-x64.dmg` (+ `.zip` для обновлений) | только с подписью Apple — без неё Орион открывает страницу релиза |
| Linux x64 | `Orion-X.Y.Z-linux-x86_64.AppImage`, `…-amd64.deb` | AppImage — да; deb — открывает страницу релиза, если не получилось |

`latest.yml`, `latest-mac.yml`, `latest-linux.yml` в релизе — по ним установленные копии узнают о новой версии.

## Выпустить версию

Поднимите версию в `package.json`, напишите, что нового, и запушьте в `main`:

```bash
npm version patch --no-git-tag-version   # 0.1.0 → 0.1.1 (minor / major — для версий крупнее)
# update/0.1.1.md — что нового (формат — update/README.md); без него npm test не пройдёт
git add update && git commit -am "0.1.1"
git push
```

Текст `update/<версия>.md` становится описанием релиза на GitHub, его же Орион зачитывает голосом: после
обновления сам предлагает рассказать, а в вопросе «Хотите обновить?» коротко говорит, что в новой версии.

`release.yml` видит, что релиза `v0.1.1` ещё нет, сам ставит тег на этот коммит и выпускает версию.
Если версия не менялась (или такой релиз уже опубликован), workflow ничего не делает. Можно и по-старому —
`npm version patch && git push --follow-tags`: тег уже будет, workflow его использует.

Упавшая сборка оставляет черновик релиза. Исправьте причину и перезапустите workflow — вкладка Actions → Release →
Run workflow: он доделает тот же черновик.

Через ~15 минут релиз опубликован. Установленные Орионы при следующем запуске скажут голосом
«Найдено обновление до версии 0.1.1. Хотите обновить?» — «да» скачивает, ставит и перезапускает.
Отключается в «Настройки → Обновления»; проверить вручную — там же или в меню значка в трее.

## Собрать у себя

```bash
npm run dist       # установщик для текущей ОС в dist/
npm run dist:dir   # только распакованная программа — быстрее, для проверки
```

Проверить собранную программу рядом с уже запущенным Орионом (своя папка данных, не мешает основной):

```powershell
$env:ORION_DATA_DIR = "$env:TEMP\orion-test"; .\dist\win-unpacked\Orion.exe
```

## Где установленная версия хранит данные

**Модели** (речь, llama.cpp и языковая модель — ~3,4 ГБ) лежат в папке `models` рядом с программой, чтобы при удалении
Ориона ушло всё сразу. На Windows это `%LOCALAPPDATA%\Programs\Orion\models`. При **обновлении** установщик эту папку
не трогает (`installer/installer.nsh`, макрос `customRemoveFiles`), при **удалении** стирает вместе с программой
и перед этим останавливает наш `llama-server`. Если рядом с программой писать нельзя (установка в Program Files;
macOS — внутри .app; пакет .deb), модели лежат в папке данных.

**Настройки, память и голоса** — в папке данных: `%APPDATA%\orion` (Windows), `~/Library/Application Support/orion`
(macOS), `~/.config/orion` (Linux). При первом запуске туда копируется `config.json` из пакета. Удаление программы
на Windows стирает и её (`deleteAppDataOnUninstall`), обновление — нет.

В разработке (`npm start`) — как раньше: `config.json` и `models/` в папке проекта.

## Языковая модель: llama.cpp или Ollama

Настройка «Движок языковой модели» (`backend` в config.json):
- `llamacpp` (по умолчанию). Орион сам качает `llama-server` из [релизов llama.cpp](https://github.com/ggml-org/llama.cpp/releases),
  сборку `llamaCpp.build`: Vulkan для Windows и Linux, Metal для macOS. Модель GGUF он берёт с Hugging Face
  (`qwen3.5:4b` → `unsloth/Qwen3.5-4B-GGUF`, Q4_K_M). Сервер запускается вместе с приложением, слушает 127.0.0.1
  на случайном порту с ключом этого запуска и работает на одной видеокарте — дискретной, если она есть.
- `ollama` — модель из установленного Ollama, как раньше.

Обновить llama.cpp: поменять `llamaCpp.build` в `src/core/config.js` на номер из релизов и прогнать `npm run eval`.
Своя модель: положить файл `.gguf` в `models/llm` и выбрать его в настройках.

## Размер сборки

- В пакет попадают только `src/`, `config.json` и рабочие зависимости — без документации, тестов и типов.
- Из Chromium оставлены локали `ru` и `en-US` (−44 МБ), установщик сжат максимально.
- Нативный модуль речи — только для своей ОС и процессора (`scripts/after-pack.js`).
- Модели речи (~0,6 ГБ), llama.cpp и языковая модель (~2,7 ГБ) в сборку не входят: Орион скачивает их при первом запуске,
  предварительно показав, что и сколько весит.

Установщик для Windows — около 88 МБ; из них ~80 МБ — сам Electron.

## macOS без подписи

Сертификата Apple нет, поэтому сборка подписана ad-hoc. При первом запуске macOS скажет, что разработчик
не проверен: правый клик по Orion.app → «Открыть», либо `xattr -cr /Applications/Orion.app`.
Чтобы обновления на macOS ставились сами, нужна подпись Developer ID: добавьте в секреты репозитория
`CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` и уберите
`CSC_IDENTITY_AUTO_DISCOVERY: 'false'` в `build.yml`.

## Что работает не везде

Системные навыки — программы, громкость, питание, «как мой компьютер», скриншоты, файлы, Wi-Fi, диктовка, Steam —
написаны на PowerShell и есть только в Windows (`platforms: ['win32']` в навыке). На macOS и Linux работают
разговор, голос, погода, курсы, поиск, напоминания, списки, память, новости, музыка с YouTube.
